# whitelabel-tuist

A multi-brand iOS restaurant menu app demonstrating white-label architecture using Tuist and Swift protocols.

## Architecture

Brand flavouring is done via a `BrandConfigurable` protocol. Each target compiles its own `BrandConfig` struct (same type name, different file) — no compile-time flags needed. Shared UI lives in `Shared/`, brand-specific entry points and configs are in their own folders.

```
Shared/               # ContentView, MenuItem, BrandConfigurable — all targets
KFC/                  # KFCApp.swift
KFCBrandConfig.swift
McDonalds/            # McDonaldsApp.swift
McDBrandConfig.swift
Dominoz/              # DominozApp.swift
DominozBrandConfig.swift
Project.swift         # Tuist project definition
Tuist.swift           # Tuist root marker
```

Each `*BrandConfig.swift` file defines a `struct BrandConfig: BrandConfigurable` with the **same type name** but belongs exclusively to its target via Tuist's `sources:`. Only one `BrandConfig` is ever compiled per target — no compile-time flags needed.

To add a new brand:
1. Create a `NewBrand/` folder with `NewBrandApp.swift`
2. Create `NewBrandConfig.swift` at the root — define `struct BrandConfig: BrandConfigurable` with the brand's values
3. Add a `.target(...)` entry in `Project.swift`, including `NewBrandConfig.swift` in `sources:` and **not** in any other target's sources
4. Run `tuist generate`

## Requirements

- Xcode 15+
- [Tuist](https://tuist.dev) — install via:
  ```bash
  curl -Ls https://install.tuist.dev | bash
  ```

## Commands

### Generate the Xcode project

```bash
tuist generate
```

Reads `Project.swift` and generates the `.xcodeproj` / `.xcworkspace`. Run this after cloning or after editing `Project.swift`.

### Edit the Tuist manifest

```bash
tuist edit
```

Opens `Project.swift` and `Tuist.swift` in Xcode with full autocomplete for the `ProjectDescription` framework. Make changes here, then run `tuist generate` to apply.

### Clean generated files

```bash
tuist clean
```

Removes derived data and cached artifacts.

## General rules

- **Never edit the `.xcodeproj` directly.** It is generated by Tuist — changes will be overwritten on the next `tuist generate`.
- **Shared code goes in `Shared/`.** Anything used by more than one target lives there.
- **Brand-specific code stays in its own folder.** Each brand folder contains only the `@main` app entry point.
- **Brand config is in `*BrandConfig.swift` at the root.** One file per brand, each named `BrandConfig` internally so shared code needs no changes.
- **Resources (assets) are declared in `Project.swift`**, not inferred. Add new `.xcassets` to the `resources:` array of the relevant target.
- **`BrandConfigurable` protocol defaults** handle fallbacks. Required properties (like `restaurantName`) have no default — the compiler will enforce them on every new brand.
